### Installation

1. Download the zip for your platform from the release assets — `windows_x64`, `linux_x64`, `macos_arm64` or `macos_x64` (the `.whl` is the pip package for the `puree` CLI; Blender does not need it)
2. In Blender, go to Edit > Preferences > Get Extensions
3. Click the dropdown menu (⌄) > Install from Disk
4. Select the downloaded zip
5. Or, from a terminal: `pip install puree-ui` and `puree init` to start a project

Requires Blender 5.1 or newer.

## What's new in 0.2.0

Puree learned to play media — natively, on the GPU, inside your panels — and to take any part of a UI fullscreen. This release also makes Linux and macOS real: every platform now ships a native core and a complete set of dependencies.

### Media playback: GIF · SVG · video · Lottie

| Format | How | Notes |
|---|---|---|
| **Animated GIF** | `img: spinner.gif` | per-frame delays and loop count honored; decoded once per file, shared between elements |
| **SVG** | `img: logo.svg` | rasterized in the Rust core at the element's exact layout size and re-rasterized on resize — crisp at any panel width |
| **Video** | `video: clip.mp4` | `.mp4` `.webm` `.mkv` `.mov` via PyAV/FFmpeg on a background decoder thread; `autoplay`, `loop`, `muted`, `volume`, `playback_rate`, `poster`, `preload` |
| **Audio** | automatic | the video's audio track plays through Blender's own audio system and drives the clock, so picture stays in sync with sound |
| **Lottie** | `lottie: anim.json` | Bodymovin JSON via rlottie; loops and autoplays by default |

Everything a browser does for free, Puree now does for free: media scrolls and clips with its container, paused or off-screen media costs zero redraws, and hot reload keeps playback position.

### Default video controls

Add `controls: true` to a `video:` node and Puree injects the `[video_controls]` bar: play/pause, drag-to-seek with click-to-jump, time and duration, mute, and fullscreen. It auto-hides while playing, and `SPACE` toggles playback once the video has been clicked. Restyle it from your own SCSS through the namespaced classes (`<video_id>_puree_vc_*`), or hide any button with `display: none`.

### Fullscreen for any container

`container.request_fullscreen()` turns any element — not just video — into a "theater mode" filling the whole editor region, laid out fresh at region size (crisp text, correctly stretched seek bar) while the rest of the UI keeps ticking underneath. `exit_fullscreen()`, `ESC`, or the controls button leave it; `container.fullscreen` reads the state and `on_fullscreen_change` handlers fire on every change. One element at a time; entering another swaps.

### Scripting: `container.media`

An HTMLMediaElement-style controller on every playable element: `play()`, `pause()`, `toggle()`, `seek(seconds)`, `stop()`; `current_time`, `duration`, `paused`, `ended`, `loop`, `muted`, `volume`, `playback_rate`, `ready_state`; and events via `media.on("play" | "pause" | "ended" | "seeked" | "timeupdate" | "error" | "fullscreenchange", fn)`.

### Engine

- **Overlay container pass** — `overlay: true` renders a container subtree *above* images and video (how the controls bar sits on the frame). Same GPU packing, no shader changes; reusable for tooltips, dropdowns and toasts over media.
- **Component defaults finally load** — a path bug meant `markdown_defaults.scss` never actually applied; the defaults loader is fixed and generalized (`components/defaults/*.scss` are prepended so your styles still win; `*.yaml` there auto-register as components).
- **Click-to-focus works** — `focusable: true` containers were never reaching the hit-tester; keyboard bindings scoped to a container now arm on click as documented.
- Text-input update logging dropped from INFO to DEBUG (it was flooding the log at timer rate).

### Platforms and packaging

- **Linux and macOS are now genuinely supported.** Previous releases shipped only the Windows native core in the pip wheel, and the macOS extension zips were missing the core dependency wheels. 0.2.0 ships the Rust core for all four platforms (`native_binaries/<platform>/`) and one extension zip per platform with a complete, platform-specific wheel set.
- Releases are now built entirely in CI on all four platforms from a tag push, with a manual dry-run mode; toolchains are pinned so a release builds with the same compiler that was tested.
- `just wheels` fetches dependency wheels for every declared platform on any machine and rewrites the manifest safely.

### Documentation

New spec sections for media elements and fullscreen, the `container.media` API reference, `[video_controls]` theming, and a Media Pipeline chapter in the knowledge base (budgets, overlay-pass rationale, patterns that don't work). Demo page `08 - MEDIA` in `tests/helloworld` exercises all four formats plus fullscreen.

### Known limitations in this release

- `ESC` and `SPACE` are dispatched through Puree's keyboard handler, which only runs when the UI contains at least one text input. The fullscreen button always works.
- The controls bar fades smoothly, but its icons and labels switch instantly (images and text do not interpolate opacity yet).
- Setting `playback_rate` to anything but `1.0` mutes the audio for the duration (no pitch-preserving resampling yet).
- SVG is static (no SMIL/CSS animation); Lottie accepts Bodymovin `.json` only, not `.lottie` archives.
- Adding a new media node while the UI is running (hot reload or `add_child`) needs a UI restart to get its image instance and controls.
- Text inputs inside a fullscreened subtree keep their normal-mode position.

> [!WARNING]
> **Breaking change** — `img:` values now require the full filename with extension:
> `img: my_icon.png` instead of `img: my_icon`. Subfolders under `assets/` are
> supported (`img: icons/play.png`). Extensionless values render nothing and log
> a "did you mean" error in the Puree log.

> [!IMPORTANT]
> Video (PyAV/FFmpeg) and Lottie (rlottie) decoders now **ship bundled** with Puree —
> `video:` / `lottie:` / animated media work out of the box, no per-addon wheels and no
> `puree init --with-video/--with-lottie` flags anymore. Size impact: +19–37 MB per
> platform (windows-x64 +27.9 MB, linux-x64 +36.6 MB, macos-arm64 +18.9 MB,
> macos-x64 +23.3 MB). A missing decoder still degrades gracefully (poster/blank + one
> warning) instead of crashing.
