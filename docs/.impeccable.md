## Project Identity

- **Name**: Puree
- **What it is**: GPU-accelerated UI framework for Blender addons
- **Tech**: YAML (structure) + SCSS (styling) + Python (interactivity), rendered via ModernGL compute shaders with Taffy/Stretchable (Rust) flexbox/grid layout
- **Runs inside**: Blender panels (sidebar, properties, floating)

## Target Audience

- Blender addon developers who want rich, custom UI beyond Blender's built-in widgets
- Technical artists and pipeline TDs building studio tools
- Developers familiar with web concepts (CSS, flexbox) working in Blender

## Brand Personality

- **Technical precision** — It's a rendering engine. Confidence in code quality matters.
- **Creative empowerment** — Enables UIs that were impossible in Blender before.
- **Modern craft** — Not flashy or trend-chasing. Thoughtful, refined, intentional.

## Aesthetic Direction

- Dark-first: Designed for Blender's dark viewport. Backgrounds use deep charcoals, not pure black.
- High contrast text: Light text on dark surfaces. Avoid low-contrast gray-on-gray.
- Accent colors should be purposeful, not decorative. Use them to guide attention.
- Rounded corners: moderate (6–12px). Avoid both sharp-edged brutalism and pill-shaped everything.
- Spacing: generous but not wasteful. Blender panels are often narrow (250–400px).
- Anti-patterns: No neon-on-dark "gamer" aesthetics. No cyan/purple AI gradients. No gratuitous glows or shadows.

## Typography

- Default font family: NeueMontreal (Regular, Bold, Medium, Italic variants in `fonts/`)
- Body text: 12–14px
- Headings: 16–24px
- Labels/captions: 10–12px
- Font selection uses YAML `font:` attribute, not CSS `font-family`

## Color Philosophy

- Tint neutrals toward the brand hue — never use pure gray
- Background hierarchy: transparent → deep dark → slightly lighter → surface
- Text hierarchy: bright primary → dimmed secondary → muted tertiary
- Accent: one dominant color, used sparingly for CTAs and focus states
- Danger/warning/success: conventional colors but tinted to match palette

## Layout Principles

- Blender panels are typically 250–400px wide
- Vertical scrolling is the primary navigation pattern
- Sidebar + main content is a common layout
- Components should work at different panel widths (use % widths, flex-grow)
- Avoid horizontal scrolling

## Component Patterns

- Components live in `components/` directory (YAML + SCSS pairs)
- Parameters use `"{{name, 'default'}}"` syntax
- SCSS variables use `!default` for overridability
- Children are namespaced: `instance_child_name`
- Prefer composition of small components over monolithic ones

## What NOT To Do

- Don't use `calc()`, `em`, `rem`, `vw/vh`, `transform`, `@keyframes`
- Don't put layout properties (width, padding, gap) in `:hover`/`:active`
- Don't use `::before`/`::after`, attribute selectors, `:is()`, `:where()`
- Don't use `font-family` in CSS (use YAML `font:`)
- Don't use hyphens in YAML node names (underscores only)
- Don't forget `mark_dirty()` after runtime property changes
- Don't use multiple box-shadows or radial/conic gradients
