### Raster / caching behavior
- Raster size = aspect-FIT of the intrinsic size into the element's content box (`fit_size`: largest integer size fitting the box at intrinsic ratio, `round()`, min 1x1). The content box is read from `instance.size` - identical to the block's mask_width/mask_height (extract_images emits width==mask_width; documented in `_box_size`).
- Re-raster: tick compares the live box to the rastered-for box; drift > 1 px per axis starts a 150 ms debounce (`RESIZE_DEBOUNCE_S`); any further change restarts it; when stable -> re-raster + texture swap + `changed=True` that tick; drift back within tolerance cancels. During the pending window `is_active()` is True.
- Cache: module-level `(abs path) -> OrderedDict[(w, h) -> bytes]`, LRU capped at 2 sizes per path (`CACHE_SIZES_PER_PATH`) - drag-resize bounce re-uploads from CPU bytes instead of re-rasterizing. Intrinsic sizes cached per abs path (`probe_svg` runs once per file). CPU caches survive `shutdown()` (same policy as the GIF decode cache; no module-level GPU cache exists for SVG - textures are per-element and dropped by `release()`); `clear_cache()` purges both.
- Fonts: `get_fonts_dir()` -> `<addon root>/fonts` (via `get_addon_root()`, `__file__` fallback outside the package) passed on every rasterize; the Rust side loads system fonts once per process and merges each new dir once.

### VideoSource lifecycle / threading design
- **Optional dep**: `import av` only inside `_import_av()`; module imports clean without it. Missing av => `ready_state='unsupported'`, poster (via `image_manager.resolve`, guarded so headless tests run without bpy) or nothing, exactly ONE session-wide warning ("video support requires the 'av' package - add the PyAV wheel to your addon manifest").
- **preload**: `metadata` (default) opens/probes duration+size/closes (`ready_state='metadata'`); `auto` also synchronously decodes+shows frame 0 (`'ready'`); `none` does nothing until `play()`/`seek()` (poster shown if set). `autoplay` calls `play()` at attach. Probe rebuilds the clock with the real duration (always still paused at 0 at that point).
- **One daemon thread per PLAYING video** (`puree-video-<file>`), owning its av container open->decode->close (in its `finally`). Queue: `queue.Queue(maxsize=6)` of `(generation, pts_seconds, width, height, rgba_bytes)` - dims ride along (task said `(pts, bytes)`; superset). Backpressure: (a) pacing - the thread naps while a frame is > 0.25 s ahead of the clock (wrap-aware for loops: a next-iteration frame's distance is time-until-wrap), which is also what makes pause cheap; (b) on a full queue it waits <= 0.25 s for space then DROPS OLDEST and retries.
- **Seek**: main thread bumps a generation counter + target under a lock, sets a doorbell event; thread `container.seek(keyframe <= target, backward=True)` + guarded `flush_buffers()`, then decode-forward discarding `pts < target-eps`. Stale-generation queue items are discarded main-thread-side; `_seek_display` shows the first post-seek frame immediately (so paused seeks display). Verified: seek(20/30) lands within +-0.03 s on the demo clip (test tolerance +-0.5 s).
- **EOF**: loop -> `container.seek(0)` and keep decoding (main-thread `_classify` handles the wrap: frames > dur/2 AHEAD of the clock are previous-iteration leftovers = drop, > dur/2 BEHIND are next-iteration = hold until the clock wraps); non-loop -> park <= 2 s (a quick replay reuses the warm container via a seek request) then exit; `clock.ended` -> controller fires `ended`. `play()` after ended seeks clock+demuxer to 0 (HTML replay parity - note `MediaClock.play()` alone no-ops on a never-paused ended clock).
- **Pause**: freezes the clock => pacing parks the thread; after ~2 s grace the thread exits and closes the container. `play()`/`seek()`/tick's self-heal restart a dead thread, resuming at `clock.current_time`. Stop-events are per-thread objects so a restart can never revive a stopping thread.
- **Tick (main thread, the only gpu toucher)**: pulls the best `pts <= t` frame (newest wins = catch-up; one future frame held as `_pending`), uploads via the shared `decoders.gif._upload_texture` (SRGB8_A8-with-RGBA8-fallback probe cache reused), 3-texture `deque` ring keeps in-flight draws safe, swaps `instance.texture`, keeps Phase 1's stub-reset self-heal.
- **Flip**: overlay quad samples v=0 at the bottom -> frames flipped bottom-up like the Rust GIF decoder. Decision: `frame.reformat(format='rgba')` (av-native, no numpy hard dep) + `flip_rgba()` - numpy negative-stride copy when importable (Blender ships numpy), stride-aware pure-bytes row slicing otherwise. RGBA from video reformat is opaque => premultiplied == straight, no premult pass (rare alpha-carrying videos would fringe - documented v1 limitation).
- **Teardown**: `release()` (from attach-reconcile and `MediaManager.shutdown()`) signals stop, joins <= 1 s (daemon regardless - can't hang Blender), drains queue, clears ring/textures/instance. Tested: zero `puree-video-*` threads and zero new non-daemon threads after `shutdown()`.

### Audio lifecycle + master-clock design (as implemented)
- **Ownership**: each VideoSource lazily creates ONE `AudioTrack` (`_ensure_audio()`, first time audio is actually wanted) and opens it on `self.path`; a muted-forever video never touches aud. - **Policy predicate** `_audio_should_play()`: `has_audio` AND ready_state not unsupported/error AND `not muted` AND rate == 1.0 (`_rate_blocks_audio()`). Callers add the clock state; aud availability is checked at the track (`_ensure_audio` returns None when inert).
- **Master clock** (`_sync_audio(now)`, called from `tick()` BEFORE `_pull_frame()` so frame selection follows the corrected clock): when PLAYING + policy true + live handle -> read `track.position`; `|clock.current_time - audio_pos| > 0.08 s` -> `clock.seek(audio_pos)` (direct resync, v1 - no slewing). Guards: skip when audio is within 80 ms of its own end (let ended/wrap logic run), skip cross-iteration deltas (`|delta| > duration/2`). Otherwise (muted / no audio / rate != 1 / aud missing / handle dead) the monotonic MediaClock drives and audio is silent. A handle that stopped at the audio stream's natural end (audio shorter than video) is NOT auto-restarted - restarting past its end would stop again every tick; silence until ended/wrap/transition.
- **Loop wrap**: `_last_media_time` tracks the previous tick's clock time while audio is active (reset to None in every inactive branch and on seeks); a backwards jump > duration/2 = wrap -> `_audio_align(t, restart=True)` reseeks audio to ~0 with the clock (the old handle normally already auto-stopped at the stream end). Ended (non-loop): `_sync_audio` stops the track once the clock reports ended.
- **Transitions** (all verified by tests): `play()` starts audio at `clock.current_time` (fresh handle; replay-after-ended forces restart; double-play on a running source leaves the in-sync handle alone); `pause()` -> `track.pause()` (handle parked alive - decision: pause-in-place is cheap and robust with aud, and `play()` re-aligns with a fresh handle at the exact clock position anyway, sidestepping resume-invalid-handle edge cases); `seek()` -> live handle `position = t` (same handle, no restart; master role kept); `set_muted(True)` -> `track.stop()`, clock continues monotonic from the same time (no jump - it was already at the audio position); `set_muted(False)` mid-play -> audio starts at current_time and becomes master; `set_volume()` -> live `handle.volume` update (also applied at start; YAML volume rides `_audio_align`'s volume sync); `stop()` -> audio stop + rewind.
- **Decision 4 enforcement** (`set_playback_rate`): rate != 1.0 -> track stopped and kept off (policy predicate false) while the rate stays != 1.0; rate back to 1.0 while playing+unmuted -> audio restored at current_time. Logged ONCE per source (`_rate_mute_logged`), only when the suppression actually mutes something (has_audio + unmuted); works for YAML-initial rates too (logged on the first would-be-start). `self.muted` is NOT flipped - suppression is an effective mute, the attribute keeps the author's value.
- **Teardown**: `VideoSource.release()` stops+releases the track (before the thread join). This is the single path used by attach-reconcile (hot reload, attr-change rebuilds) AND `MediaManager.shutdown()`, which is already wired at render.py cancel (~2433) / stop_ui (~2460) / render.unregister (~2529) / puree/__init__.py unregister (~328) and hot_reload re-attach (~378) - verified, no rewiring needed; audio simply rides the existing source-release path. The shared aud.Device intentionally survives shutdown (session singleton; only handles are per-source).

### Deviations

### rlottie facts verified (rlottie-python 1.3.8 source + empirical probes; unit tests re-assert them)
- **API**: `LottieAnimation.from_file(path)` (ctypes over `lottie_animation_from_file`; raises OSError when the file is missing or the DLL can't load); metadata via `lottie_animation_get_size() -> (w,h)`, `lottie_animation_get_totalframe()`, `lottie_animation_get_framerate()`, `lottie_animation_get_duration()`; `lottie_animation_render(frame_num=, width=, height=) -> bytes` (w*h*4); `lottie_animation_destroy()` (also from `__del__`; guarded, idempotent). `from_data`/`from_tgs`/render_async/property_override exist but are unused.
- **totalframe is INCLUSIVE**: `op - ip + 1` - the 90-frame demo timeline reports **91** while `get_duration()` returns `(op-ip)/fr = 3.0`. Playback uses the GIF model (every frame gets one native frame-time display slot), so `duration == frame_count/fps = 3.033 s` - one frame-time longer than rlottie's number; documented in the module.
- **Channel order: BGRA** - the wrapper's own `render_pillow_frame` decodes the buffer as PIL raw "BGRA"; empirically the #4772b3 core center renders bytes (179,114,70,255). Converted by `bgra_to_rgba_bottom_up` (numpy fancy-index path + pure-bytes strided-slice fallback, equality-tested).
- **PREMULTIPLIED alpha** - a 45%-opacity stroke probe renders max(channel) <= alpha; full-frame sweep of the demo: 0 violations. The R<->B swizzle preserves premultiplication - **no premultiply pass needed**, pipeline contract (premul RGBA) satisfied.
- **Row order: TOP-DOWN** - an asymmetric top-left-rect probe lands in the FIRST buffer rows; frames are therefore flipped bottom-up in the same helper (matching decode_gif/rasterize_svg and the overlay quad UVs; flip test mirrors the SVG one).
- **Aspect**: rlottie letterboxes a mismatched surface (`renderSync` keepAspectRatio default) - moot here because frames are rendered at the aspect-FIT of the intrinsic canvas into the content box (`fit_size` imported from decoders/svg.py), so surface aspect == intrinsic aspect.
- **NULL-animation hazard**: `lottie_animation_from_file` returns NULL for unparseable input and any subsequent C call on it would segfault Blender - LottieSource validates the JSON before rlottie ever sees it AND checks `animation_p` after from_file (-> `ready_state 'error'`, one error log per path).

### .json validation design (the ".json is ambiguous" problem)
`.json` registers in SOURCE_FACTORIES (so the scan/enum/dispatch derive automatically), and `LottieSource` validates ON OPEN: `validate_lottie_json` requires parseable JSON (utf-8-sig), an object root, all five mandatory Bodymovin keys (`v`, `fr`, `w`, `h`, `layers` - per the format spec), `layers` a list, `fr`/`w`/`h` positive numbers. Failure -> ONE warning per abs path per session ("lottie: 'x.json' is not a Lottie/Bodymovin document (...) - element renders nothing") and the source is an inert `'unsupported'` stub (tick False, is_active False, duration None, controls no-op) - never a crash. Validation is dependency-free and runs BEFORE the rlottie import, so a wrong file gets the accurate message even without the wheel (test-pinned). Consequence (documented): every asset-dir .json becomes a media stub in ImageManager - harmless unless referenced. `img: anim.json` also works (same factory; blocks without playback keys land on the lottie defaults - GIF-like autoplay+loop). **`.lottie` zip containers: NOT registered** - plan non-goal (v1), recorded in the module + registry comments.

### Missing-dependency degrade (mirrors av/video)
`_import_rlottie()` lazy-imports inside methods; module import is rlottie-free (isolated-load test proves it). Missing wheel -> `ready_state 'unsupported'`, poster-less (renders nothing; lottie has no poster attr), ONE session warning: "lottie support requires the 'rlottie-python' package - add its wheel to your addon manifest (lottie: elements render nothing until then)". play/seek/stop/tick all safe no-ops.

### Playback / clock
`MediaClock` built from **error-diffused per-frame delays** (`frame_delays_ms`: boundaries land on `round(i*1000/fps)`, so 30 fps yields 33/34 ms delays summing exactly - no drift at any fps) - frame resolution is `clock.frame_index(now)`, i.e. the exact GIF machinery; loop/seek/rate/ended all ride the tested clock. `autoplay`/`loop` default TRUE (lottie-player parity; plan 6.1's explicit `loop: true` is clarity, not a requirement); `playback_rate` honored (2x test); `muted`/`volume` are inert stored attrs (controller fallback assigns them - safe no-ops). Hooks provided: `play()` (with ended->seek(0) HTML replay parity), `pause()`, `seek()` (immediate frame swap while paused, GifSource pattern), `stop()` (pause + rewind + repaint), `duration`, `ready_state`, `matches_block` (attach-reconcile rebuilds on YAML attr changes - verified through the real `media_manager.attach`). Single-frame animations are `_static` (never active - idle rule). Rendering is main-thread-only per tick (no decoder thread; plan budget: 512 px <= ~3 ms rlottie CPU raster).

### Caching behavior (plan sections 5.4/10)
Budget check at the CURRENT raster size: `w*h*4*frame_count <= 32 MB` -> **progressive per-element frame cache** (`dict[frame_idx -> GPUTexture]`): each frame renders exactly once when playback first reaches it; the first loop fills the cache and later loops are swap-only (test-pinned: full 20 Hz loop, second loop adds zero renders). Over budget -> render-on-demand into a 2-texture reuse deque (current + previous, in-flight-draw safe). Resize mirrors SvgSource verbatim (+-1 px tolerance, 150 ms debounce, churn restarts, pending counts as active): settling drops ALL cached textures + the ring, re-evaluates the budget at the new size and re-renders the current frame. Caches are per element and die with `release()`; deliberately NO module-level CPU cache (unlike GIF/SVG - lottie rasters are size-dependent and cheap to reproduce; a UI restart re-renders on demand). `release()` also destroys the rlottie C handle immediately (hot reload doesn't wait for GC) - shutdown path verified (manager shutdown -> released, handle freed, registries empty).

### Decisions / deviations
1. **Frame count/duration model**: rlottie's inclusive totalframe (91) is honored - every frame gets a display slot, so `media.duration` reports `frame_count/fps` (3.033 s), one frame-time above rlottie's `get_duration()` (3.0 s). Chosen over dropping the last frame because non-seamless animations end on meaningful final frames (progress fills etc.); GIF-model parity.
2. **`_authored_media_attrs` on Container** (small scope addition, required for correctness): lottie defaults autoplay/loop TRUE but the attrs are shared with video where they default False - a plain `getattr` cannot distinguish "author wrote `autoplay: false`" from "never set". `__setattr__`'s existing coercion branch now records post-construction assignments of the media bool/float attrs into a per-instance set (created at the END of `__init__`, so construction records nothing; YAML/component-params/scripts all record). extract_images consults it only for lottie autoplay/loop. Shared defaults, video behavior and all 154 existing tests untouched.
3. **Precedence warning shape**: img+video keeps the byte-identical Phase 3 warning; lottie adds one same-pattern warning naming the winner (img > video > lottie). A node setting all three logs both warnings (each true).
4. **No preload attr for lottie**: a parsed animation knows all metadata and renders on demand - ready_state jumps none->ready (or unsupported/error). `poster:` likewise not consumed (plan gives lottie no poster; degrade is render-nothing).
5. **Per-element GPU cache, no cross-element/module cache** (vs GIF's shared per-file decode): lottie frames depend on the per-element raster size, and two same-file elements usually differ in box; sharing would complicate release/budget bookkeeping for marginal wins. Recorded as a future optimization if a page ever shows N copies of one animation at one size.
6. **`stop()` implemented** (video parity) rather than relying on the controller's clock fallback - the fallback would leave a stale frame visible while paused (GIF has that gap; lottie repaints via its seek hook).
7. Warning granularity: missing-wheel = once per session (like av); invalid/unopenable file = once per abs path per session (`_warned_paths`; validation failures warn, open failures error-log).
8. rlottie-python pins `lottie_configure_model_cache_size(0)` at construction (its own default) - rlottie's internal model cache stays disabled; our caching is the explicit budgeted layer above.
